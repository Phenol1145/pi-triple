# PTH 与 PTL 目标范围再界定

背景：Pi-Triple 原定义把 PTL 与 PTH 描述为单仓双产品的前后端关系（PTL = 本地交互层/前端，PTH = 服务器端任务内核/agent 联邦平台），并通过 HTTP 桥把两者绑定为"前端 → 后端"的产品定位。

决定（2026-08-15）：解除前后端关联，重新界定二者范围：

- **PTH 是自耦自然语言解释器**：输入自然语言意图，直接产出执行结果（解释即执行）。任务池、角色路由、沙箱等只作为内部实现机制存在，不再是对外定位。
- **PTL 是基于 pi 的多环境共存平台**：只管理多个 pi 环境（模板隔离、并行共存）；调用 PTH 属于外部能力，不是平台内环境。
- **PTL 通过 PTH CLI 调用 PTH**，PTH CLI 是规范调用接口；现有 HTTP 桥降级为兼容通道，不再定义两者关系。
- 后续方向：为 PTH 设计专属前端，并提供不使用容器的 PTH 版本。

理由：两个产品的演化方向与部署形态已经分叉。继续用前后端定义会让 PTH 被绑定为 PTL 的执行后端，也阻碍 PTH 独立成完整产品；把关系收缩为"PTL 可用 PTH CLI 调用"后，两者可以各自演进。

**Consequences**：

- `CONTEXT.md` 与总览文档（`ARCHITECTURE.md`、`README.md`、`docs/README.md`）的定位表述以本决定为准。
- `docs/superpowers/plans/` 下的模块化迁移计划保持参考计划状态；任何实施前须按新范围重新评估。
- 代码现状仍以 HTTP 桥与 `pth` server 为主，PTH CLI 目前是 HTTP 网关的封装；CLI 作为规范接口、无容器版本与 PTH 专属前端均为待落地方向。
- `docs/ptl/`、`docs/pth/` 子文档中的旧"交互层/执行层"表述留待各自文档的后续修订，不以本决定为一次全部重写。
