## 本版内容

### 1. W8：PTL 任务派发与交互逻辑（P0–P3 全阶段）

- **P0 契约与盖章**：`payload.delivery` TaskDelivery 契约（parent/path/lineageId/replyTo/
  artifactRef）；外部入口强制显式路由盖章；终态 `payload.result` 回写（64KiB 截断 +
  失败摘要；sandbox 产物只走 artifactRef 引用）。
- **P1 delegate/await**：组织权矩阵（直接子类型白名单 + planner/governor 执行族补充权 +
  origin 全树；sensor/controller 排除）服务端 fail-fast；`tasks.delegate/await` 工具面
  按投递权条件注入；MID 目标由服务端 `delegateTarget` 直接填 `assigned_role`。
- **P2 事件驱动回流**：`tasks.await` 未终态写 `payload.dispatchWait` 并挂起
  （`task-await-suspended` → retryable requeue）；子终态 → `task-dispatch-notifier`
  写 `payload.childResult`；`tasks.resume()` 重跑续接；取消沿派发树传播
  （`POST /api/v1/kernel/tasks/:id/cancel` 递归 CTE）；PTL `ptl hub kernel wait <id>
  --follow` 打印逐层 path/childResult。
- **P3 穿透接口位**：`skill:penetrate:<child>` 四段式 + 机读边信息；注册校验强制
  parent→child 命中组织权矩阵（memory-keeper 维护面调用即拒绝）。

### 2. 0.16 任务拓扑：工具面收口 + 穿透执行面

- **0.16.4 分拆 worker 工具面收口**：九个内部类型（actuator/executor/explorer/governor/
  researcher/analyst/developer/tester/prospector）actionTools 统一收为
  `[execTs, nav, cache]`（基本工具 + 直接子类型投递）；五 MID prompt「注明建议路由」
  改写为「tasks.delegate 派发 + tasks.await 回收」；sensor/controller 治理族根豁免。
- **0.16.3 穿透执行面**：`tasks.penetrate({to,title,text})` 显式原语——父 worker 任务内
  同进程嵌套直呼子 agent（跳过任务池往返）；执行期机器校验（组织权实时重验 + skill
  official 门槛 + 机读边归属）；深度限 1（嵌套子 kernel 不注入 taskControl/penetration）；
  失败报错由父决策；计量以 `domain=penetration` 汇入父任务面。

### 3. skill staged 审核流全链接通（N2 Phase 3 闭合）

- `PTH_SKILL_WRITE_POLICY=staged` 显式开启后打通「memory-keeper 提案 →
  controller:adversarial 对抗性审核 → 监督批准 → memory-keeper 执行」全链：
  `skills.maintain.propose` 落库即发 `skill.proposal.created` 事件 → 系统 trigger
  `skill-proposal-review` 事件驱动派发审核任务 → 审核 pass/reject → 批准后执行写入；
  staged 模式下 `maintain.write` 要求携带已批准提案 id（否则引导走 propose）。
- 审核面收窄：审核能力仅注入 controller:adversarial；端到端 4 例（全链 pass/reject/
  审核面收窄）+ trigger 注册断言 6→7。
- **运维注意**：staged 需显式开启（`PTH_SKILL_WRITE_POLICY=staged`）且
  controller:adversarial 需入 batch 配比（`PTH_WORKER_ROLES`）才形成闭环；缺省 manual
  模式行为不变。

### 4. worker 子进程健康/卡死检测（§9 L2 可观测性补齐）

- batch 子进程心跳自报（rss/cpu + 心跳时间戳）；`listBatches`/`obs.batches` 健康面：
  **healthy / stale / dead** 三态 + `heartbeatLagMs`；陈旧阈值
  `PTH_BATCH_HEALTH_STALE_MS`（默认 15s，运行时可调——与 watchdog 同档）。

### 5. 工程与概念

- **flaky 根治**：`BatchManager.addWorker` 与 removeWorker 同构改回执语义（等
  `worker-status:added`）——`batch-manager-fork` 集成测试全量并发抖动消除。
- **0.17 worker 优化四层次**概念录入：工具（OpenAI tool call 协议层）/工具包/空间 =
  可见性管理；四层次（工具面/单工具/记忆/规则）+ N14 账本（sensor/controller 四维细分
  待设计）；**A2 裁决：开一等工具注册通道**（0.3.6 并联代偿落地第一步）。
- **fork-session 并行执行协议**：`docs/pth/parallel-lanes.md` 车道账本 + worktree 隔离 +
  认领/热点/决策纪律（本版内容由 L1–L4 并行 lane 产出）。

## 行为/运维变更（升级必读）

- **内部类型工具面收窄**：九个中间层角色不再暴露执行核/生产核工具（execPy/execBash/
  dev/debug/write 下沉叶子类型）——既有派发中任务若依赖中间层亲执行可能行为变化；
  capabilities 未收（引导级收口，ts 程序面能力保留）。
- **新增 PTC 能力**：`tasks.penetrate`（PTC 契约 14→15）；`tasks.delegate/await/resume`
  仅组织权角色注入（W8 P1 起）。
- **API 新增**：`POST /api/v1/kernel/tasks/:id/cancel`（`{recursive?}`）；PTL
  `ptl hub kernel wait <id> [--follow]` / `ptl hub kernel tasks cancel <id> [--recursive]`。
- **配置新增/变更**：`PTH_BATCH_HEALTH_STALE_MS`（新增——batch 心跳陈旧阈值，默认
  15s，runtime 可调）；`PTH_SKILL_WRITE_POLICY=staged` 链路本版接通（既有键——staged
  需配合 controller:adversarial 入 batch 配比）。
