# framework 发行计划（pi-triple npm 发布）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 发布 pi-triple 到 npm——根包（ptl CLI）+ 子包生态（@pi-triple/*），发行版不含用户使用痕迹。

**Architecture:** 发布形态 = **方案 B（子包生态）**：`@pi-triple/{framework,shared,infra,mailbox,extensions-in-container}` 各自发布 + 根 `pi-triple` 聚合。子包可独立安装（`pi install npm:@pi-triple/mailbox`）。

**Tech Stack:** npm pack/publish、prepublishOnly 构建链、.npmignore/files 白名单。零新依赖。

## Global Constraints

- **发行版不含用户痕迹**（核心约束）：
  - 排除：zlib 脚本、bfc、lifelab 相关、`~/.pi-triple/` 数据（pi-config/providers/sessions/workspaces）、`docs/superpowers/` 个人讨论记录、`.pi-platform-data/`
  - 验证：`npm pack --dry-run` 后 grep 痕迹关键词 = 0 命中
- 发布形态：方案 B（子包生态）——5 子包 + 1 根包
- **发布前待修**（ledger 记录）：
  - infra/mailbox/extensions-in-container 的 main/exports 指向 src（.ts）——**必须改 dist**（发布即炸）
  - 子包缺 files 字段
  - shared dist gitignored——prepublishOnly 需 build
  - 根包 files 需含子包 package.json（若方案 B 子包独立发布，根包应只依赖/聚合）
- 版本：根 0.1.1 → 子包 0.1.0（首次发布）
- 提交风格：chore(release): 中文摘要

### Task 2: 痕迹排除清单 + 验证脚本

**Files:**
- Create: `scripts/check-release-clean.sh`（发行痕迹验证脚本）

**Interfaces:**
- Consumes: 无
- Produces: 可重复执行的痕迹检查（npm pack --dry-run + grep 关键词）

- [ ] **Step 1: 写验证脚本**

```bash
# scripts/check-release-clean.sh
#!/bin/bash
# 发行痕迹检查：npm pack --dry-run 输出中不得含用户痕迹关键词
KEYWORDS="zlib|bfc|lifelab|pi-config|providers.json|/sessions/|/workspaces/|\.pi-platform|superpowers|\.pi-triple"
OUT=$(npm pack --dry-run 2>&1)
HITS=$(echo "$OUT" | grep -iE "$KEYWORDS" | grep -v "node_modules" | head -20)
if [ -n "$HITS" ]; then
  echo "❌ 发行包含用户痕迹:"
  echo "$HITS"
  exit 1
fi
echo "✅ 发行包干净（无用户痕迹）"
echo "文件数: $(echo "$OUT" | grep -c 'notice.*B ')"
```

- [ ] **Step 2: 运行验证（当前应通过——已确认无痕迹）**

```bash
chmod +x scripts/check-release-clean.sh && ./scripts/check-release-clean.sh
```

- [ ] **Step 3: 提交**

```bash
git commit -m "chore(release): 发行痕迹验证脚本——npm pack 后 grep 关键词排除用户数据"
```

### Task 3: prepublishOnly 构建链 + 根包聚合调整

**Files:**
- Modify: `package.json`（prepublishOnly 脚本 + files 调整）

**Interfaces:**
- Consumes: 构建链（tsc -p packages/*）
- Produces: 发布前自动 build（shared dist 生成——解决 gitignored 问题）

- [ ] **Step 1: 写失败测试（prepublishOnly 存在）**

```bash
node -e "const p = require('./package.json'); if (!p.scripts?.prepublishOnly) throw new Error('prepublishOnly missing'); console.log('OK')"
```

- [ ] **Step 2: 修 package.json**

```json
// scripts 加
"prepublishOnly": "npm run build"
// files 确认：子包独立发布后，根包 files 只含根级产物 + 子包 package.json（供 npm i -g pi-triple 时子包可解析——或根包依赖子包 npm 包）
```

**决策点**：根包 `pi-triple` 的聚合方式——
- A. 根包 `dependencies` 声明 `@pi-triple/*`（npm 安装时拉子包）——标准 monorepo 发布
- B. 根包 files 含子包 dist + package.json（自包含单包）——体积大但无外部依赖

**推荐 A**（标准做法）：根包 dependencies 指向已发布的子包版本。

- [ ] **Step 3: 验证**

```bash
npm run build && npm pack --dry-run
```

- [ ] **Step 4: 提交**

```bash
git commit -m "chore(release): prepublishOnly 构建链 + 根包聚合（dependencies 指向子包）"
```
