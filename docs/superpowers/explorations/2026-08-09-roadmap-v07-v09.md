# Pi-Triple 路线图（v0.7 → v0.9）

> 2026-08-09 用户规划 · v0.6.0 发布后的三个版本方向

## v0.7 — 兼容性扩展接口 + 容器化抽象

### 兼容性扩展接口
定义统一扩展接口，兼容既有生态：
- **pi extension 生态**（@earendil-works/pi-coding-agent 的 ExtensionAPI——pi 自身的扩展机制：tools/commands/events/skills）
- **OpenClaw plugin 生态**（第三方插件体系——调研对齐）
- 目标：PTH 的 kernel 能力面可插拔（kernel 类型/能力函数/工具面——第三方扩展接入）

### 容器化抽象
- 容器后端接口（声明式部署描述 → 后端实现：docker/podman/k8s/colima）
- 迁移前提已就绪：env 独立（PTH_*）/ 镜像独立（Dockerfile×2）/ 卷语义 / 健康检查 / sandbox 网络契约

## v0.8 — 系统自持 + PTL 调试工具

### 系统自持（主动性能调节）
- 监视 → 诊断 → **自动调节**（perf.set 自动——闭环：指标异常 → 自动调参 → 复测验证）
- 现有基础：perf.set 运行时调参 + descheduler 角色级扩缩 + 四层指标
- 目标：无需人工/agent 介入的自愈性能闭环

### PTL 侧调试工具完善
- TUI 调试体验（日志/追踪/会话诊断）

## v0.9 — 自修改状态

### agent 重写 kernel（Node → 编译型）
- **动机**：Node 进程占用过重（batch node 110MB 基线 × N——内存是大头）
- **方向**：用 developer（agent 自主）把 kernel 核心重写为编译型语言（C/Rust/Go 候选）
- **自修改**：agent 系统自己重写自己的运行时——自修改闭环

## 版本节奏备忘
- v0.6.0 ✅（编译核 + 调试核 + 单大 batch + 自动调度）
- v0.7 ⏳ 兼容性扩展接口 + 容器化抽象
- v0.8 系统自持 + PTL 调试工具
- v0.9 自修改（agent 重写 kernel——Node → 编译型）
